# Можливі питання на захисті та орієнтовні відповіді

1. **Чому модульний моноліт?** Він зберігає транзакційні межі бронювання і зменшує операційну складність для невеликої команди; розділення на сервіси розглядається за виміряної потреби.
2. **Як запобігається подвійне бронювання?** Запит перевіряє правила на сервері, а PostgreSQL exclusion constraint над часовими діапазонами в єдиній таблиці блокує перетини навіть за конкурентних запитів. Це потрібно підтвердити міграцією і тестом на PostgreSQL.
3. **Чому використовують Decimal?** Для фінансових значень потрібна десяткова арифметика та явне округлення; двійковий `float` може накопичувати похибку.
4. **Як ізолюються компанії?** API має обмежувати queryset і перевіряти належність користувача до компанії на сервері; приховування елементів інтерфейсу не є контролем доступу. Автоматизовані негативні тести є обов'язковими.
5. **Чи обробляє система реальні платежі?** Ні. Поточний код містить лише початкову схему платежів; інтеграція і webhook-підпис не реалізовані та мають залишатися вимкненими.
6. **Чи перевірено продуктивність?** Поки що немає валідних вимірів. Для висновків потрібні контрольована конфігурація, набір даних, сценарії навантаження й зафіксовані результати.
